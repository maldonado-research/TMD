# Static audit of the clone-fitness comparison code

The inspected author-repository script for Figure 7 of Avecilla et al. (2022) supplies a concrete data-selection boundary: its competition-assay distribution retains **positive estimated fitness coefficients**, after removing identifiers that contain the ancestral-strain label `DGY1657`. This agrees with the paper’s stated comparison of beneficial variants. It is a sign filter, not a significance test, and therefore cannot be identified with Lauer et al. (2018)'s 18/28 significantly fitter clones. The row membership and number retained remain unknown because the input CSV was not acquired. [Article](https://doi.org/10.1371/journal.pbio.3001633); [immutable inspected code blob](https://api.github.com/repos/graceave/cnv_sims_inference/git/blobs/14efd06f001d17c8c039751496a36c1b7b0efc18).

The source is an actual authenticated code artifact: `figures/Figure7andSup.Rmd`, 9,832 decoded bytes, Git blob SHA-1 `14efd06f001d17c8c039751496a36c1b7b0efc18`, SHA-256 `5eff8f43410a7dd254cbcc1c358dde96a2ce0573c0f03b605884bc21f8d50b28`. Its content-addressed identity was checked against the nontruncated repository tree and the decoded API response. This authenticates the inspected repository snapshot; it does not establish that the bytes equal the exact script executed for the published figure. Only static reading was performed. No author code, model, formula or fitting procedure was executed.

The script exposes three further dependencies that need actual input records before a row-level claim:

- It reads `clone_fitness_pergen.csv` for the competition distribution and `data_props_Lauer2018.csv` for the example competition plot, where it selects strain `DGY1734`. Neither file is present in the inspected repository tree.
- Barcode fitness results receive identifiers from a separate filtered-barcode file by **row position**, then join to `CNV_barcodes.csv` on barcode and population. The script maps `bc04`-named files to the population label `bc01`. Input order, alias validity and join cardinality cannot be checked without those records; no mismatch has been established.
- An unmatched barcode receives the plotting label `noCNV`; this is an absence-of-match classification, not an independently DNA-genotyped negative. The barcode fitness distribution also retains only positive estimates. Separately, the trajectory plot removes specified zero-count patterns and renormalizes retained counts at each time point. These plotting filters are not a census of all founders or mutation events.

The intended S4 clone workbook remains **unrecovered**. The article authenticates its identity as supplement `pbio.3000069.s021.xlsx`, but no XLSX bytes or clone rows were obtained. Publisher redirection and a PMC browser challenge did not yield the workbook. The 29 sequenced-clone and 28 competition-clone cohorts therefore remain unresolved at the identifier level. Neither this code audit nor the inspected repository inventories supply the fluorescence–genotype–fitness crosswalk, reporter-negative truth set, missing-clone reasons or lost-lineage records. [Original study and supplement listing](https://doi.org/10.1371/journal.pbio.3000069).

The useful result is a narrower interpretation of the comparison: it uses selected positive fitness estimates and shared source populations. It adds no native SBW25 W/A/M panel, biological fit, mutation-birth observer or independent establishment measurement. The 26 study inputs and 18 planning inputs remain NULL, with frozen model, evaluation and methods 0.6.0 unchanged. Raw article and source-code captures remain outside the public payload; `CODE_AUDIT.json` records the original dependency and selection audit.
